# HOL 原版性能对齐闸（PARITY GATE）

> **由来**：2026-11-25 用户裁定——「最近老是做出一个比 HOL 更差的方案，还要无脑推进……始终
> 按照 HOL 原版作为性能目标，不对齐需要明确的原因解释。」本文件是该裁定的执行章程；
> `AGENTS.md` §7.3 是硬规则摘要。wt1 差距的量化来历见 `docs/priority-queue.md` 续1511
> （数字只在账本层存一份，这里只引用）。
>
> **适用范围**：所有**方法 / 架构 / 证书单位 / 发射形态**的选型与迭代，含已在飞车道
> （下一轮迭代即适用；不追溯否定已落库的标准三件）。

## §1 一句话规则

**选型前先量原版。** 默认目标 = 原版 HOL 同一对象的实现；比原版差，要么给出结构性原因与
可实现下界，要么改设计；两者都做不到的工单不许开工（在飞车道：不许进下一轮）。

## §2 六维基线（每张卡都要量全）

| 维 | 定义 | HOL 侧取值 | 我方取值 |
|---|---|---|---|
| D1 义务数 | 同一数学对象拆成的证明义务条数 | 原版定理/lemma/pass/glue 计数（`rg` 可复算） | 叶 / pass / 箱计数 |
| D2 证书单位 | 数据的组织单位：每单位存什么、存哪、谁生成 | 原版数据文件与生成器结构 | 每箱/每 pass 源文件与内容 |
| D3 源码字节 | 人写 + 生成的规则与数据源码 | `wc -c`，注明目录 | kit + 生成器输出 |
| D4 产物字节 | 落盘缓存（olean / 检查点 / 数据文件） | LCF：≈0（定理是内存值）；有缓存另计 | olean / 输出文件 |
| D5 计算成本 | 生成与校验的墙钟 × 核数、峰值 RSS | 原版文档或复跑 | `/usr/bin/time -l` 实测 |
| D6 信任类别 | 公理 / 内核 `decide` / native / 反射 | HOL 内核 + 何种扩展 | 标准三 / `decide` / `native_decide` |

**取数纪律**：每个 HOL 数字带 `file:line` 或可复跑命令；每个我方数字带实测 commit + 命令。
取不到的写 `UNRESOLVED`，不许估、不许拿别的对象凑。

## §3 判定词（只用这五类，禁「差不多」「基本对齐」「可接受」）

| 判词 | 条件 | 后果 |
|---|---|---|
| `PARITY` | 每一维 ≤1.2× 原版 | 可开工 |
| `WITHIN-BAND` | 1.2–2×，且写明「这一维为什么消不掉 + 消除计划 + 复测点」 | 可开工（卡上留痕） |
| `OVER-BAND` | >2× 且无结构性理由 | **设计无效**；只能用户明批后开工，编排者不得自批 |
| `STRUCTURAL-DIFF` | 该维在原版/我方之间结构不可比（例：LCF 不落 proof object vs DTT 必存 proof term） | **只豁免该维**；必须给出**可实现下界**（按证书内容位数估计 + 至少一个实测最小样例），目标 ≤1.2× 下界 |
| `NO-COUNTERPART` | 原版没有同一数学对象 | 明写；禁止拿邻近对象当基线；该维按 `STRUCTURAL-DIFF` 处理（给下界） |

**带宽是默认值，不是验收线**（与 AGENTS §7.2 一致）：带宽只评成本，不判数学；任何维度
都不许用「预算 / 平台 / 时间」当未对齐理由。

## §5 流程（谁在哪一步）

1. **T1 基线**：新对象进入选型前，派 `hol-parity-analyst` 产出 `PARITY_BASELINE.md`
   （六维 + `file:line`）。该 agent 零 Lean、只读原版、只写快照。
2. **T2 卡片**：同一 agent 按 §4 出卡并给判定；卡片进工单，**无卡不派 Lean 车道**。
3. **T3 执行**：车道按卡开工；交付时回填实测列。任一转差 ⇒ 停、报告、回到 T1。
4. **T4 复审**：每轮收线，agent 对在飞/新交付架构做一次 `PARITY_AUDIT`——查
   「方案先行、对齐后补」（先有实现后补卡、卡无出处、结构性差异当全维豁免、
   用预算解释未对齐）。
5. **例外**：`OVER-BAND` 只能用户明批；批文入 pq，卡片记「用户明批 <日期>」。

## §6 预研 agent（`hol-parity-analyst`）

- 定位：**性能对照的预研 / 审计 agent**，不是实现 agent；零 Lean 编译、不改主仓 tracked 文件。
- 三类任务：`BASELINE` / `CARD` / `AUDIT`（定义见 `.zcode/agents/hol-parity-analyst.md`）。
- 判词必须可复算：脚本 + 输出 + 命令入 `~/c17_backup/lane_snapshots/<lane>/`。
- 禁止：把 `reference/` 以外的东西当原版；用采样/估算冒充实测；「无同对象」时拿邻近对象凑。

## §7 已登记的结构性差异

| # | 维 | 差异 | 下界怎么给 |
|---|---|---|---|
| SD-1 | D4 产物字节 | HOL Light 是 LCF：定理是内存值、证明是脚本，不落 proof object；Lean 4 每个声明都落 olean | 按「证书内容的可编码位数 + Lean 最小样例 olean」估下界；目标 ≤1.2× 下界（不是 ≤1.2× HOL） |

> 新 SD 条目必须有 `file:line` 证据，由 T1 基线登记进卡片；结构性差异不是免死金牌——
> 它只替换比较对象（原版 → 可实现下界），不取消比较。
