    命中 docstring 散文（如 `axiom face on the axprobe sample)`）不算。
12. **陈旧 olean 会让 `#print axioms` 撒谎**（2026-11-06 实测，差点报错数）：olean 里存着
    声明的公理名表，`#print axioms` 直接照答，**不检查依赖是否新鲜**。删了 3 条 `native_decide`
    公理、重编了 Assembly，根面**仍打印 628** —— 因为 `Kepler/Final.olean` 没重编。
    ⇒ pit 2 扩大为：**探针路径上每个模块都必须重建**。判据：`grep -rl <新删的名字>
    .lake/build/lib/lean/` 只在 `.trace`/`.ilean` 命中即可（`.olean` 命中 = 真还有引用）。
13. **`#print axioms` 遍历陈述类型，不只是证明体**（2026-11-06 实测）：
    ```
    def badProp : Prop := sorry
    theorem t1 (h : badProp) : True := trivial   -- 证明体一次都没碰 h
    't1' depends on axioms: [sorryAx]
    ```
    ⇒ `def X : Prop := sorry` 是**给每个消费者陈述注射 `sorryAx` 的注射器**，证明写得再干净也没用。
    全树此类注射器只剩 `PackingAuto25.lean:90` 的 `ox3q1hP25`（`grep -rn 'def .*: *Prop *:= *sorry'`）。
    推论：任何"填本体就能闭"的评估，先检查目标陈述里有没有这种 def。
14. **olean 缓存每个声明的公理名表**（2026-11-06 实测，`2ef062e8` 时的教训）：
    `#print axioms` **打印该缓存，不重算依赖**。所以「消除一条公理」之后，
    **从改动点到根的每一层都必须重编**，否则读到的还是旧的（更高的）数字。
    实测：goodlist 波三把 14 条公理消掉后，第一次打根面仍是 601；重编
    `Kepler/Graphs/TameClassification`（1 s）+ `Kepler/Graphs`（2 s）两层后才变 **587**。
    推论：
    (a) **这类落库的根面只能由编排者验**，车道无法自验（它拿不到根）；
    (b) **Δ 可作机械判据** —— 期望 Δ 精确等于被消除的公理条数。601−14=587 吻合，
        反过来同时证明"没有误消除别的公理"且"没有引入新公理"；
    (c) 定位办法：`grep -rln 'import <被改模块>'` 找出直接消费者，逐层向上重编到 `Assembly`。
