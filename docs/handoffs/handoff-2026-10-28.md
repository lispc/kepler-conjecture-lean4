## 5. 闸工程手册（踩过的坑，全部有实录）

1. 标准调用（从 `lean/` 起）：
   `LANE_FILES="Kepler/<路径>" THM="<文件内声明>" lock_build nice -n 19 bash
   scripts/auto_gate.sh <lean/起路径> <THM>`；LANE_FILES **逗号分隔**、路径
   必须从 `lean/` 起全径。
2. STATEMENT-FIX：`GATE_MODE=STATEMENT-FIX SF_PATCH=<归档补丁,仓根相对>
   SF_ITEM=<n>`；proposals 条目须在 `## N.` 与首个 `###` 之间含 `(a) HOL`；
   工作树唯一改动 = 已应用 patch；patch 头禁时间戳。**多集合比较按 `+++ b/lean/$FILE`
   单文件节进行**（sffile-w1 实测）：两 item 共 patch 兼容，但多文件 patch 须以各文件为
   `$FILE` 各闸一次才全覆盖（LANE_FILES 其余文件仅放脏不比对）。
3. **手写补丁必须规范化**为应用后真实 `git diff`（删加对 vs 上下文行致
   多集合错位）；规范化程序 = apply → `git diff HEAD -- lean/` → checkout →
   覆盖归档 → apply --check。
4. **zsh 不分词**：pathspec 一律用数组 `SPEC=(...); git add "${SPEC[@]}"`。
5. 邻接漂移：`git apply -3`（三路合并按 blob 基线对齐）。
6. 构建锁：`/tmp/kepler_build_lock.dir`，mem gate ≥50% 空闲，TTL 30min；
   跨仓库（A2 克隆 vs 主仓）物理无冲突，单文件 `lake env lean` typecheck
   可作无锁反馈（本轮已用，窄口）。
7. **⚠ 雷区（2026-10-28 傍晚实爆）：Lake 包健康检查删包**。机制
   （Materialize.lean:66-78）：`updateGitRepo` 用 `git remote get-url`（Git.lean:187）
   读包远端——被用户全局 `url.git@github.com:.insteadof https://github.com/`
   展开成 ssh——与 manifest 的 https 比较不等，realPath 比较抛异常被吞 →
   `sameUrl=false` → **`removeDirAll` 整个包目录后重克隆**（当日重克隆失败）。
   触发条件（Materialize.lean:237-262 精确）= **包目录存在且其 HEAD ≠ manifest
   钉的 rev** 时才进 `updateGitRepo`（rev 一致直接短路——所以主仓日常
   `lake build`/`lake env` 永不触发，此前没炸）；实爆场景 = 某 /tmp 工作区
